Zeval

Zeval explores how teams can evaluate AI agents using real interaction logs. It turns repeated user corrections, unfinished tasks and recovery attempts into reviewable cases, then uses those cases for regression checks before the next release.

The question

Aggregate scores can conceal the failures that matter most to users. How can an agent team find those failures systematically and tell whether a new version fixes them?

Evaluation loop

  • Find friction: identify repeated requests, corrections and abandoned interactions in conversation traces.
  • Inspect recovery: separate outright failures from cases in which the agent corrected itself.
  • Create cases: turn recurring patterns into concrete regression examples that reviewers can inspect.
  • Check releases: run those examples again as the agent changes.
Logs→Failure patterns→Reviewable cases→Regression checks

What I take into research

Reliable evaluation needs traceable evidence, clear failure categories and cases that remain useful after a model or prompt changes. Those ideas also shape how I think about scientific agents.
